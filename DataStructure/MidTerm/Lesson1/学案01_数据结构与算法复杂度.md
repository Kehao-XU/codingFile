## 一、概念骨架

**数据**：信息的载体，能被程序识别处理的符号集合（数值与非数值）。
**数据元素**：数据的基本单位，程序里作为一个整体处理，由若干**数据项**组成；也叫元素、结点、记录。
**数据对象**：性质相同的数据元素的集合，如全体学生记录。

**数据结构** DS = {D, R}：一个数据对象 D，加上 D 中元素之间的关系 R。落到工程上是三件事：

| 层面 | 含义 | 内容 |
|---|---|---|
| 逻辑结构 | 元素间抽象关系，与存储无关 | 线性（线性表）、非线性（树、图） |
| 存储结构 | 逻辑结构在机器上的实现 | 顺序、链接、索引、散列（前两者主用于内存，后两者主用于外存） |
| 运算 | 施加于元素上的操作 | 查找、插入、删除、修改、排序 |

同一个逻辑结构可以有多种存储实现，代价完全不同。课件用通讯录把这条主线走了一遍：

```
顺序表          查找 O(n)
有序顺序表+折半   查找 O(log n)，插入 O(n)（要移动元素）
单链表          插入 O(1)（已定位），查找 O(n)（不能折半）
二叉搜索树       平均 O(log n)，退化成单枝时 O(n)
平衡二叉树       O(log n) 稳定
```

后面每一章都在重复这个动作：换一种存法，换一组代价。

**抽象数据类型 ADT**：值集合 + 定义在其上的一组操作，只描述逻辑特性，不涉及实现，做到信息隐藏、使用与实现分离。课件用自然数举例，注意 `Add` 溢出时返回 MaxInt、`Sub` 下溢时返回 0——ADT 的每个操作在边界上必须有确定语义，这是它区别于"接口草图"的地方。

```
ADT NaturalNumber
  Zero()        -> 0
  IsZero(x)     -> x == 0
  Add(x, y)     -> x+y <= MaxInt ? x+y : MaxInt
  Sub(x, y)     -> x < y ? 0 : x-y
  Equal(x, y)   -> x == y
  Successor(x)  -> x < MaxInt ? x+1 : x
```

## 二、算法评价：为什么必须事前估计

算法的性能标准五条：正确性、可使用性、可读性、效率、健壮性。前三条靠测试和读代码，效率不行——同一段代码在快机器上跑 1 ms、在慢机器上跑 10 ms，编译器不同目标码长度也不同，测出来的数字只对"这台机器 + 这组数据"成立。后期测试能验证正确性和可用性，不能比较算法优劣。

所以效率走**事前估计**：建立问题规模 n 与时间开销 T(n)、空间开销 S(n) 的关系。这个关系与机器无关，才是可以进教材、进面试、进选型文档的东西。

## 三、程序步：课件特有的精确计数法（重点）

**程序步**：语法或语义上有意义的指令序列，其执行时间与实例特性无关。约定：声明语句 0 步，表达式 1 步，赋值/返回 1 步；函数调用本身 1 步，再加上被调函数体执行的步数（`x = sum(R, n)` 这条赋值语句共 1+3n+4 = 3n+5 步）。`for` 头按"判断 1 步 + 自增 1 步"计，执行 n 次循环体时头部共执行 n+1 次，即 2n+2 步。

> 旁注｜程序步这套计数法来自 Knuth 的 TAOCP，国内教材沿用了它。它是为了让你**手算出一个可靠的阶梯**，而不是精确预判耗时——所以后面还要再抽象一次。工程里没人真的去数程序步。

两种数法：插计数变量 `count`，或建频度表。课件用的是后者，也更好查错。

### 例：迭代求和

```c
float sum(float a[], int n) {
    float s = 0.0;                     // 1 步
    for (int i = 0; i < n; i++)        // 2 步/次 × (n+1) 次
        s += a[i];                     // 1 步/次 × n 次
    return s;                          // 1 步
}
```

| 语句 | 一次执行步数 | 执行频度 | 执行步数 |
|---|---|---|---|
| `s = 0.0` | 1 | 1 | 1 |
| `for (...)` | 2 | n+1 | 2n+2 |
| `s += a[i]` | 1 | n | n |
| `return s` | 1 | 1 | 1 |
| | | | **3n+4** |

### 例：递归求和

```c
float rsum(float a[], int n) {
    if (n <= 0) return 0;                        // n=0：1+1 = 2 步
    else return rsum(a, n-1) + a[n-1];           // n>0：1+2+T(n-1)
}
```

递推式：T(0) = 2，T(n) = 3 + T(n-1)，展开得 **T(n) = 3n+2**。

3n+4 与 3n+2 只差 2 步，阶都是 O(n)。递归真正的代价不在步数，而在每层调用占一个工作记录，空间 O(n)。程序步的价值是"可数、可比、与机器无关"，不是精确时间——这也是下一步做渐进分析、把常数抽象为 1 的原因。

## 四、渐进分析：只留主导项（重点）

### 大 O 的定义

存在正整数 c > 0 和 $n_0 > 0$，使 $\forall n \ge n_0$ 有 T(n) ≤ c·f(n)，则记 T(n) = O(f(n))。

用定义验证三个课件例子：

- T(n) = 3n+2：n ≥ 2 时 3n+2 ≤ 3n+n = 4n，取 c = 4、$n_0 = 2$
- $T(n) = 10n^2+4n+2$：n ≥ 5 时 $\le 11n^2$，取 c = 11、$n_0 = 5$
- T(n) = 9：取 c = 9、$n_0 = 1$，即 O(1)

考试若要求"给出 c 和 $n_0$"，按上面写法凑出来即可，c 不必最小。

### 三条规则

设 m、n 是问题规模，$T_1(m) = O(f(m))$，$T_2(n) = O(g(n))$，则：

- 加法规则：$T_1(m) + T_2(n) = O(max(f(m), g(n)))$——两段代码先后执行，取慢的那段
- 乘法规则：$T_1(m) \cdot T_2(n) = O(f(m) \cdot g(n))$——一段代码嵌在另一段里，阶相乘
- 简化规则：$T(n) = a_mn^m + \ldots + a_1n + a_0$（$a_m > 0$）$\implies T(n) = O(n^m)$

> 旁注｜三条规则对 O 成立，对 Ω 也成立（把 ≤ 换成 ≥ 即可），所以可以直接套在 Θ 上；但不是所有渐进记号都能这么运算，小 o、小 ω 就不满足加法规则。

增长率排序：$c < \log_2 n < n < n\log_2 n < n^2 < n^3 < 2^n < 3^n < n!$。前三档可用，$n^2$、$n^3$ 勉强，$2^n$ 起 n 稍大就跑不动。

### 计算套路

1. 找**关键操作**：最内层循环里那条语句，或递归体里每次调用都执行的那条。
2. 数频度，先得到与 n 的**精确函数**，别急着取阶。
3. 用规则取阶。

六种典型场合：

| 场合 | 关键动作 | 例子 |
|---|---|---|
| 单层循环 | 数循环次数 | `for(i=0;i<n;i++)` → O(n) |
| 并列循环 | 加法规则 | `exam(m, n)`（m 行 n 列数组先逐行求和、再逐行打印）中 O(mn) + O(m) = O(mn) |
| 嵌套循环 | 乘法规则 | 矩阵乘法 $3n^3+5n^2+4n+2 = O(n^3)$；冒泡排序 $O(n^2)$ |
| 步长非 1 | 设循环体执行 k 次，解 $2^k = n$ 得 $k = \log_2n$ | `i = i*2` 型循环 → O(log n) |
| 内层依赖外层 | 写求和式 | 下方例一 |
| 递归 | 列递推式 | Fact：T(n) = C+T(n-1) = O(n) |

### 例一：内层受外层控制

```c
for (int k = 1; k <= n; k *= 2)      // 外层变量 k 依次取 1, 2, 4, ...
    for (int j = 1; j <= k; j++)     // 内层变量 j 从 1 数到 k
        sum++;
```

定义 $m = \lfloor \log_2n\rfloor$（即 $\log_2n$ 向下取整），则 k 依次取 $1, 2, 2^2, \ldots, 2^m$，外层循环体执行 m+1 次。用 r = 0, 1, …, m 表示这是外层第 r+1 次执行，那么此时 $k = 2^r$，内层执行 $2^r$ 次。内层总次数为

$$
\sum_{r=0}^{m} 2^r = 2^{m+1} - 1
$$

由 $2^m \le n < 2^{m+1}$ 得 $2^{m+1} - 1 < 2n$，所以是 **O(n)**，不是 O(nlog n)。内层次数跟着外层变量走，乘规则不适用，必须写成求和。

### 例二：递归看递推式

- `Fact(n)`：T(n) = C + T(n-1)，T(1) = D，展开得 O(n)：调用 n 次，每层 O(1)
- `Fib(n)`：`Fib(n-1) + Fib(n-2)`，每次调用分裂成两次，调用次数为 2Fib(n+1)-1，即指数级（每深一层，调用量约乘 1.618）
- `Hanoi(n)`：T(n) = 2T(n-1)+1，T(1) = 1，展开得 $2^n-1$（第 6 讲会重算）

递归复杂度由"每层几次调用 × 每层代价 × 层数"决定，数递归次数不够。

### Ω 与 Θ

存在 c > 0、$n_0 > 0$ 使 $\forall n \ge n_0$ 有 T(n) ≥ c·f(n)，则 T(n) = Ω(f(n))；上下界同阶则 T(n) = Θ(f(n))。

O 是上界，所以 O(n) 的算法写成 $O(n^2)$ 逻辑上不算错，只是没有信息量；约定写最紧的上界。

### 最好、最坏、平均

以顺序查找为例：最好 1 次比较 O(1)；最坏 n 次 O(n)；平均 (n+1)/2 = O(n)。

平均情况必须带分布假设（这里假设等概率且查找成功）。题目不给假设时，平均复杂度这个答案是不成立的；工程上数据分布往往偏离均匀，这是平均分析最容易失效的地方。

## 五、空间复杂度

存储开销分两部分：

- 固定部分（静态空间）：指令代码、常数、简单变量、定长数组与对象成员
- 可变部分（动态空间）：与实例规模有关的变量、递归工作栈、`new/delete` 动态申请的空间

做渐进分析时只保留与 n 有关的部分，不计输入数据本身占的空间。例：两数交换 O(1)；复制一个 n 元数组 O(n)；递归深度 d 的算法 O(d)。

## 六、速查表

| 量级 | 典型来源 | 后面会在哪出现 |
|---|---|---|
| O(1) | 下标访问、栈顶操作、哈希查找（期望） | 顺序表 Get、Push/Pop |
| O(log n) | 折半、`i*=2`、堆的上浮下沉 | 折半查找、堆调整 |
| O(n) | 一次遍历、自底向上建堆 | 求表长、建堆 |
| O(n log n) | 堆排序、归并、快排平均 | 排序章 |
| $O(n^2)$ | 双重循环、冒泡/插入/选择 | 排序章 |
| $O(2^n)$ | 子集枚举、朴素 Hanoi、递归 Fib | 递归章 |
| O(n!) | 全排列 | 回溯 |

工程上这张表直接对应选型：随机访问多就用连续内存（`vector`），中间频繁增删才考虑链表（`list`），键值查找上 `unordered_map`，`std::sort` 用的是 [introsort](https://en.cppreference.com/w/cpp/algorithm/sort)，把最坏情况压到 O(nlog n)。

> 旁注｜这里出现的容器都是 C++ 标准库的名字，本课不要求会用，只要知道"复杂度决定选型"这件事在工业代码里是常态。第 2、3 讲会分别手写 `vector` 和 `list` 的雏形。

### 任务 2：计时实验——验证阶，而不是验证常数

对 $n = 2\times 10^3$ 到 $1.6\times 10^4$ 分别跑下面两个函数，记录单次调用的耗时，算 t(2n)/t(n)。`clock()` 只有毫秒级精度，所以 O(n) 那一侧要重复跑多次再除，这正是课件"算法的后期测试"一页给的做法。

代码里用 `s = s*31 + i` 而不是 `s += i`：编译器会把求和折叠成公式，那样测出来的就不是循环了。这个坑本身就是"后期测试不可靠"的一个实例。

```c
#include <stdio.h>
#include <time.h>

long long sumOn(int n) {                 // O(n)
    long long s = 0;
    for (int i = 0; i < n; i++) s = s * 31 + i;
    return s;
}

long long sumOn2(int n) {                // O(n^2)
    long long s = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) s = s * 31 + j;
    return s;
}

volatile long long sink;                 // 防止编译器把无副作用的调用优化掉
double perCall(long long (*f)(int), int n, int reps) {
    clock_t t1 = clock();
    for (int r = 0; r < reps; r++) sink = f(n);
    clock_t t2 = clock();
    return (double)(t2 - t1) / CLOCKS_PER_SEC / reps;
}

int main(void) {
    int ns[] = {2000, 4000, 8000, 16000};
    for (int k = 0; k < 4; k++) {
        int n = ns[k];
        printf("n=%6d  O(n)=%7.3fus  O(n^2)=%9.3fms\n",
               n,
               perCall(sumOn, n, 10000) * 1e6,
               perCall(sumOn2, n, 1) * 1e3);
    }
    return 0;
}
```

参考输出（gcc -O2，你的数字会不同）：

```
n=  2000  O(n)=  2.600us  O(n^2)=    1.000ms
n=  4000  O(n)=  5.100us  O(n^2)=   24.000ms
n=  8000  O(n)= 10.500us  O(n^2)=   82.000ms
n= 16000  O(n)= 20.300us  O(n^2)=  330.000ms
```

要观察到的：n 每翻一倍，O(n) 那列约翻倍，$O(n^2)$ 那列约四倍。第一行已经贴着 `clock()` 的 1 ms 精度，看后三行更准。绝对值随机器变，比值不变——这是"阶与机器无关"的实验版本。

## 八、易错点

1. 程序步 ≠ 运行时间。先算精确步数，再抽象成阶；两件事分开做。
2. 嵌套循环不能无条件相乘，内层上界依赖外层时必须写求和式（例一）。
3. 递归只看"调用了几次"会错，要看递推式；`f(n/2)+f(n/2)` 是 O(n) 而不是 O(log n)。
4. O 是上界。写 $O(n^2)$ 描述线性算法不算错但无意义，约定写最紧的。
5. 空间复杂度只算辅助空间，不含输入；但递归工作栈要算进去。

**任务 1**：`m = a[0]` 1 步；`i = 1` 1 步；比较 `i < n` 共 n 次；自增 n-1 次；`if` 判断 n-1 次；赋值最多 n-1 次；`return` 1 步。

- 最坏（每次 `a[i] > m` 都成立，n-1 次赋值）：1+1+n+(n-1)+(n-1)+(n-1)+1 = **4n**
- 最好（从不赋值）：**4n-1**
- 阶：O(n)，最好最坏同阶

**任务 2**：n 翻倍时 O(n) 耗时约翻倍，$O(n^2)$ 约四倍。若某档明显偏离，顺序排查三件事：计时精度不够（重复次数太少）、被编译器优化掉（累加被折叠成公式）、缓存与分支预测影响（n 太小）。加大 n 或加重复次数再测。

**任务 3**：x 在表内均匀分布时平均比较次数 ≈ (n+1)/2；x 在表外时恒为 n 次，平均退化为最坏。这解释了顺序查找平均 O(n) 的前提条件。

**任务 4**：

- (a) 循环 n 次，每次 O(1) → O(n)
- (b) $\sum (n-i) = n(n+1)/2 \to O(n^2)$
- (c) $3^k \le n$，$k = \log_3 n \to O(\log n)$
- (d) T(n) = 2T(n/2)+O(1)，展开为 $2^{\log_2 n} = n \to O(n)$
