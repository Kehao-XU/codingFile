# 学案 03 · 链表

对应课件 `课件/chapter-2-2-full.pptx`（93 页）｜教材：殷人昆《数据结构》第 3 版，第 2 章后半

顺序表的两笔账算清了：插入删除要搬元素，容量还得预先估。链表用"每个结点自带下一站地址"换掉了这两笔账，代价是丢掉了随机访问。

---

## 一、结点与指针

**单链表**的每个**结点**由两部分组成：数据域 `data` 存元素，指针域 `link` 存下一个结点的地址。整条表由**头指针** `first` 指向第一个结点，最后一个结点的 `link` 为 `NULL`（下面代码里写 `nullptr`）。

```
first → [a1|•] → [a2|•] → … → [an|^]
```

结点之间的逻辑顺序由指针决定，物理位置随意，所以链表能"边用边申请"，也不会因为中间插入而搬动任何元素。

**插入**：设 `current` 指向"新结点要插在它后面"的那个结点，`newNode` 是待插入结点。只需两句，顺序不能颠倒：

```cpp
newNode->link = current->link;   // 1. 新结点先接住后继
current->link = newNode;         // 2. 再让前驱指向新结点
```

反过来写，第一步就把 `current` 的后继覆盖了，后面的链全丢。表头插入是它的特例（`current` 换成头指针）：

```cpp
newNode->link = first;
first = newNode;
```

**删除** `current` 的后继：

```cpp
del = current->link;             // 记下要删的结点
current->link = del->link;       // 跨过它
delete del;                      // 释放
```

两个动作都是常数时间，但前提是**已经拿到 `current`**。找这个位置仍要沿链走，所以链表插入删除的真实代价是"定位 O(n) + 改指针 O(1)"，不能只说 O(1)。

## 二、带表头结点

在表的最前面加一个不存数据的**表头结点**，头指针永远指向它。好处有两个：

- 空表与非空表的操作统一了，插入删除不用为"是不是第一个结点"写特例；
- 可以顺便存表长、尾指针等整表信息。

代价是多一个结点、多一层间接。课件的插入/删除实现都假设有表头结点，考试写代码也建议这么写，能少一半边界判断。

**建表的两种插法**：

| 插法 | 做法 | 结果 | 时间 |
|---|---|---|---|
| 头插（`CreateListF`） | 每个新结点插在表头结点之后 | 与输入**逆序** | O(n) |
| 尾插（`CreateListR`） | 维护尾指针 `last`，新结点接在尾部 | 与输入**同序** | O(n) |

尾插若要每次从头找尾巴就会退化成 $O(n^2)$，所以必须额外维护 `last` 指针——这是"用空间换时间"在链表上的第一个例子。

## 三、四种链表对照

| | 找后继 | 找前驱 | 判表尾 | 典型用途 |
|---|---|---|---|---|
| 单链表 | O(1) | O(n) | `p->link == NULL` | 只需单向扫描 |
| 循环链表 | O(1) | O(n) | `p->link == first` | 环形调度、约瑟夫 |
| 双向链表 | O(1) | O(1) | 带头结点的循环形态下无表尾 | 需要前后移动 |
| 静态链表 | O(1) | O(n) | `link == -1` | 无指针的语言 |

**循环链表**把最后一个结点的 `link` 指回表头，于是"从任意结点出发都能走遍全表"。判断走到链尾不能再比 `NULL`，要比 `p->link == first`。

带**尾指针** `rear` 的循环链表还有个小便宜：表头就是 `rear->link`，所以在表头插入、在表尾插入都是 O(1)；删表头也 O(1)，删表尾仍要 O(n)（得找前驱）。

**约瑟夫问题**是循环链表的标准用例：n 个人围成一圈，从第 1 个开始报数，报到 m 的人出列，下一个人重新从 1 报，直到剩一人。用循环链表模拟，每轮走 m-1 步，删掉当前结点。

**双向链表**的每个结点有 `lLink`（前驱）和 `rLink`（后继）。在 `p` 之后插入 `s`，四步，顺序同样不能乱：

```cpp
s->lLink = p;                 // 1. s 接上前驱
s->rLink = p->rLink;          // 2. s 接上后继
p->rLink->lLink = s;          // 3. 后继回指 s（此时 p->rLink 还没改）
p->rLink = s;                 // 4. 最后才改 p 的后继
```

删除 `p` 只要两句，因为前驱后继都拿得到：

```cpp
p->rLink->lLink = p->lLink;
p->lLink->rLink = p->rLink;
```

第 3 步必须在第 4 步之前：一旦先改了 `p->rLink`，`p->rLink->lLink` 指的就是 `s` 自己了。

**静态链表**用数组模拟链表：数组下标代替指针，`link` 域存的是下标，-1 表示结束；再用一个 `avail` 维护空闲结点链，分配就是"从 avail 摘一个"，释放就是"挂回 avail 头部"。它存在的意义是给没有指针的语言（早期 BASIC、Fortran）提供链表能力，今天更多作为一种"数组 + 索引"的编码技巧出现（比如并查集、某些内存池）。

> 旁注｜课件花了不少篇幅讲**链表游标类 Iterator**：把"遍历链表"从 `List` 类里拆出来，单独做成一个持有 `current` 指针的对象，避免每加一种遍历需求就往 `List` 里塞一个成员函数。这就是 C++ 标准库 iterator 的思路，第 7、8 讲遍历二叉树时还会用到同一个分离手法。

## 四、代价表

| 操作 | 顺序表 | 单链表（带头结点） |
|---|---|---|
| 取第 i 个元素 | O(1) | O(i) |
| 按值查找 | O(n) | O(n) |
| 已知位置插入/删除 | O(n)，搬元素 | O(1)，改指针 |
| 未知位置插入/删除 | O(n) 定位 + O(n) 搬 | O(n) 定位 + O(1) 改 |
| 空间 | 预分配，可能浪费或溢出 | 每结点多一个指针，按需分配 |
| 缓存友好性 | 连续访问，命中率高 | 指针跳跃，命中率低 |

最后一行课本不讲，但决定了工程选择：同样 O(n) 的遍历，数组通常比链表快几倍，因为 CPU 预取对连续内存有效。所以"链表插入快"只在小数据量、插入位置已知、或元素很大不宜搬动时才真正兑现。

四个任务，都是课件作业里的题：

## 六、易错点

1. 插入的两句顺序颠倒，直接丢链。判断标准：第一条语句里用到的后继，必须在被覆盖之前读出来。
2. 双向链表插入的四步，第 4 步（改 `p->rLink`）必须最后做。
3. 删除结点后忘记 `delete`，或者 `delete` 之后继续用它的 `link`（应该先存到 `del` 里）。
4. 循环链表的终止条件是 `p->link == first`，不是 `NULL`；空表的判断是 `first->link == first`（带头结点时）。
5. 尾插不维护尾指针，每次从表头找尾，建表退化成 $O(n^2)$。
6. 链表长度不是 O(1)：必须遍历一遍数出来，除非在表头结点里存了 count。

## 八、一句话带走

链表把"物理相邻"换成了"指针相邻"：插入删除只改指针，代价是所有按位置的操作都要先走一遍。
