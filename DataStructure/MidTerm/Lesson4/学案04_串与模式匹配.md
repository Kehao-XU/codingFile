# 学案 04 · 串与模式匹配

对应课件 `课件/chapter-3-full.pptx`（65 页）｜教材：殷人昆《数据结构》第 3 版，第 3 章

串的逻辑结构就是线性表，区别全在操作上：线性表以"一个元素"为单位增删，串以"一整段"为单位处理。本讲真正的主角是最后一节——在一段长文本里找一段短模式，BF、KR、KMP、BM 四种做法。

---

## 一、定义与术语

设 V 是字符集，V 上的字符组成的有限序列叫**串**，记 s = "$a_0a_1\ldots a_{n-1}$"（n ≥ 0）。n 是**长度**，不含结尾的 `'\0'`；n = 0 是**空串**。

串 s 中任一连续子序列叫 s 的**子串**，s 叫**主串**。字符在序列中的序号叫**位置**，从 0 开始；子串在主串中的位置 = 它第 0 个字符在主串中的位置。

基本操作：`Assign`（初始化）、`GetLen`、`IsEmpty`、`Empty`（清空）、`Comp`（比较）、`Concat`（拼接）、`SubString`（取子串）、`Find`（求子串出现位置）。后四个是本讲要实现的。

三种存储：

| 方式 | 做法 | 特点 |
|---|---|---|
| 定长数组 | `char ch[N+1]` | 简单，超长会被截断 |
| 动态数组 | `char *ch` + new | 可按实际长度分配，增删要重新分配 |
| 块链 | 每个结点存一段（如 80 字符） | 插入删除方便，但存储密度低 |

**存储密度** = 串值实际占用的位数 / 实际分配的位数。块链每个结点带一个指针，密度必然小于 1——这是拿空间换灵活性。

> 旁注｜课件里的 `DString` 类（构造、赋值、`operator+=`、`GetSub`）是这三种存储中"动态数组"的一份完整实现，考代码题的概率不高，看懂 `GetSub` 的越界处理即可：`nPos + nCount - 1 >= nLen` 时把 `nCount` 截断成 `nLen - nPos`。

## 二、问题定义

**模式匹配**：在长串 text（长 n）中找短串 pattern（长 m）的一次或多次出现，返回 pattern 首字符在 text 中的下标。

四种算法共用同一个框架：把 pattern 对齐到 text 的某个**窗口**，比较窗口内字符；不匹配就把窗口向右平移。区别只在**每次平移多远**和**怎么比较**。

| 算法 | 比较方式 | 每次右移 | 预处理 | 最坏 | 实际 |
|---|---|---|---|---|---|
| BF | 左→右逐个 | 1 | 无 | O(mn) | O(mn) |
| KR | 哈希值 | 1 | O(m) | O(mn) | 期望 O(n) |
| KMP | 左→右逐个 | 由 next 决定 | O(m) | O(m+n) | O(m+n) |
| BM | 右→左逐个 | 坏字符/好后缀取大 | O(m) | O(mn) | 通常亚线性 |

---

## 三、BF：最朴素的做法

逐个字符比，失配就把窗口右移一位重来。最好情况前 m 个字符就匹配，O(m)；最坏情况每次都是"前 m-1 个对上、最后一个不对"，比如 pattern = "aaab"、text = "aaaa…a"，总共比较 m(n-m+1) 次，即 O(mn)。

BF 不是一无是处：不需要预处理、常数空间、比较顺序随意（可以右到左、可以跳着比）。它的问题有两个：一是逐字符比太慢，二是"太健忘"——已经比对过的信息被完全丢弃。

---

## 四、KR：把 m 个字符压成一个数

KR 把窗口内的 m 个字符看成一个 m 位二进制数，求哈希值，先比哈希、再比内容：

$$
hash(w[0..m-1]) = (w[0] \cdot 2^{m-1} + w[1] \cdot 2^{m-2} + \ldots + w[m-1]) \bmod q
$$

窗口右移一位时不必重算，用**滚动哈希**：

$$
rehash(a, b, h) = ((h - a \cdot 2^{m-1}) \cdot 2 + b) \bmod q
$$

其中 a 是移出窗口的字符，b 是新移入的字符，h 是上一窗口的哈希值。一步 O(1)。

- 预处理 O(m)，之后每步 O(1)，期望 O(n)；
- 最坏情况每次都哈希冲突且每次冲突都比较了 m 个字符，退化为 O(mn)，比 BF 还慢（多了哈希开销）；
- 冲突率取决于 q 的选取，实践上取一个大素数即可。

## 五、KMP：让模式串自己告诉你怎么跳

### 5.1 为什么能跳

设某一趟在 text 位置 s+j 与 pattern 位置 j 失配，那么在失配之前已经有

```
p[0..j-1] == t[s..s+j-1]
```

如果 pattern 自己的前缀和后缀有一段重合，即存在 k 使 `p[0..k] == p[j-k-1..j-1]`，那么窗口右移后，这段后缀对应的 text 就不必再比——它已经等于 pattern 的前缀了。于是：

- text 的扫描指针**永不回退**；
- pattern 的指针退回 `next[j]`。

换句话说，KMP 把"窗口移动多少"这个决定，从 text 身上转移到了 pattern 自己的**自相似结构**上。

### 5.2 next 的定义

**`next[j]` 等于 $p[0..j-1]$ 这段里，最长的「相等真前缀与真后缀」的长度**，并规定 `next[0] = -1`。

- 「真前缀」指不含最后一个字符的前缀，「真后缀」同理，所以这个长度一定小于 $j$。
- 直白地说：模式在 $p[j]$ 处失配时，`next[j]` 告诉你模式该退到第几个字符继续比。
- `-1` 是个哨兵：$j=0$ 就失配时，模式已无处可退，只能让 text 前进一格。

手算时就按这个定义逐列数，不要背递推公式。

### 5.3 手算 next

以 p = "abaabcac"（m = 8）为例，逐列看「p[j] 之前那段，最长相等前后缀有多长」：

| j | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| p[j] | a | b | a | a | b | c | a | c |
| next[j] | -1 | 0 | 0 | 1 | 1 | 2 | 0 | 1 |

- j = 3：p[0..2] = "aba"，前缀 "a" 与后缀 "a" 相等且最长，长度 1，所以 next[3] = 1。
- j = 5：p[0..4] = "abaab"，前缀 "ab" 与后缀 "ab" 相等，长度 2，所以 next[5] = 2。
- j = 1：p[0..0] = "a" 只有一个字符，没有真前缀，长度 0，所以 next[1] = 0。

这条定义比 5.4 节的递推算法好记，手算时直接数「最长相等前后缀」即可。

### 5.4 递推求 next

设已知 next[j] = k，则 p[0..k-1] == p[j-k..j-1]。比较 p[k] 与 p[j]：

- 相等：next[j+1] = k+1，前后缀各延长一位；
- 不等：把 k 退到 next[k]，再比。原因是 p[0..k-1] 的后缀里可能藏着更短的匹配。

循环写出来就十几行（见 `src/match.cpp` 的 `buildNext`）。

### 5.5 失配后怎么走

```
j == 0 且失配：text 前进一格，j 保持 0
j > 0 且失配：text 不动，j = next[j]
```

text 指针单调递增，所以总比较次数不超过 O(n)，加预处理 O(m)，整体 O(m+n)。空间 O(m)。

### 5.6 再优化一格

若 `p[j] == p[next[j]]`，那退回 next[j] 之后必然还是失配，白退一次。于是把 next[j] 直接改成 next[next[j]]，这一版叫**优化后的 next**（有的教材记作 nextval）。手算时只需多问一句"退过去那个字符和刚失配的字符是不是同一个"。

## 六、BM：从右往左比，一次跳很远

BM 与 KMP 的差别在于比较方向和跳跃依据：**从右向左**逐字符比，用两个预计算表决定窗口右移多少，取两者中的**较大值**。

**坏字符规则**：失配处的 text 字符 c 称为坏字符，它出现在 pattern 的位置记为 last(c)（没出现记 -1），则

```
右移位数 = 坏字符在窗口中的下标 - last(c)
```

**好后缀规则**：已经匹配上的尾部子串叫好后缀，取其中最长的那个，看它在 pattern 里上一次出现的位置（只允许出现在头部之前），

```
右移位数 = 好后缀的位置 - 上一次出现的位置
```

例子：pattern = "EXAMPLE"，text 中出现 "S" 失配，S 在下标 6，pattern 中未出现（last = -1），右移 6-(-1) = 7 位；出现 "P" 失配时，P 在下标 6，pattern 中上一次出现在下标 4，右移 2 位。

BM 的最坏情况仍是 O(mn)（构造反例不难），但真实文本上通常接近 O(n/m) 次比较——这也是各种编辑器的 Ctrl+F 用它的原因。

> 旁注｜BM 的完整实现还要处理"好后缀在 pattern 中只出现一次"和"多个好后缀"两种情况，构造 `suffix` 与 `prefix` 两个辅助数组。本讲只要求手算位移量，代码实现了坏字符规则（见 `src/match.cpp`），足够跑出对比数据。

## 七、动手


程序做三件事：打印 "abaabcac" 与 "aaaa" 的 next 数组（含优化版），在两组输入上跑 BF、KMP、BM 并统计比较次数。

**第 1 组：最坏输入**，text = 40 个 'a' 加一个 'c'，pattern = "aaaab"。这构造让每次窗口都要比到最后一个字符才失败。

```
BF    185 次比较
KMP    82 次比较   （text 指针从不回退）
BM     37 次比较   37 次位移
```

BF 的 185 正是 5×37：37 个窗口，每个窗口 5 次比较。KMP 的 82 约等于 2n，因为每次失配回退后还要再比一次确认；它的价值在于**与 m 无关**——把 m 从 5 换成 5000，KMP 仍是 80 多次，BF 会涨到 18 万。

**第 2 组：普通英文句子**，pattern = "searches"。

```
BF     59 次比较
KMP   108 次比较
BM     16 次比较
```

这组数字值得多看一眼：BF 反而比 KMP 少一半，BM 最少。原因有三个——

- 自然文本里 pattern 前缀重复度低，KMP 的 next 表几乎全是 0，回退后一场空，却仍要做"失配—回退—再比"两次；
- BF 在自然文本上平均只要比 1~2 个字符就能排除一个窗口，常数极小；
- BM 从右往左比，靠坏字符表一次跳 6~7 位，7 次位移就扫完 75 个字符。

所以 KMP 不是"更快的 BF"，它是"最坏情况有上界的 BF"。文本随机、pattern 短时，BF 通常够用；文本和 pattern 都高度重复（DNA、二进制日志）时，KMP 的上界才是刚需。BM 的问题相反：平均极快，最坏仍可构造到 O(mn)。
## 八、易错点

1. next 的下标约定有 -1 版和 0 版两套，考试先看题目用的是哪套，别把两个表混着背。
2. j = 0 失配时必须让 text 前进，否则死循环；写 KMP 的 while 循环时先处理这个分支。
3. 手算 next 时容易把"最长相等前后缀"算成"最长公共子串"，前者必须一个顶在开头、一个顶在结尾。
4. KR 的 `rehash` 里减去的应该是移出字符乘 $2^{m-1}$，写成 $2^m$ 就对不上了。
5. 存储密度恒小于 1（块链），不是"越小越好"——太小说明指针开销大，块要开到合适大小。
6. 比较次数的最坏情况不等于平均情况。KR 期望 O(n)、BF 最坏 O(mn)，但 KR 的最坏比 BF 还差。

## 十、一句话带走

BF 逐位试，KR 用哈希跳过整窗比较，KMP 用 pattern 的自相似性跳过整段，BM 从尾部比并且一次跳到位——四者都在回答同一个问题：失配之后，已知的信息还能用多少。
