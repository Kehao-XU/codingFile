# 学案 06 · 递归和广义表

对应课件 `课件/chapter-5-full.pptx`（80 页）｜教材：殷人昆《数据结构》第 3 版，第 5 章

递归不是一种"技巧"，而是把问题描述出来的方法。这一讲要说清两件事：递归为什么一定要栈，以及多深的递归会吃掉多少空间；后半段是广义表——线性表的推广，也是第 7 讲递归遍历树的预演。

---

## 一、什么样的递归成立

能用递归解决的问题，通常满足三条：

1. 规模为 n 的问题可以拆成若干个规模更小的**同类**问题；
2. 小到某个界限时能**直接求解**（这个界限就是递归出口）；
3. 小问题的解能**组合**成大问题的解。

递归过程因此分两个阶段：**分解**（逐层下探到出口）和**合成**（逐层返回时把结果拼起来）。阶乘是最小的例子：

```cpp
long fact(long n) {
    if (n == 0) return 1;      // 出口
    return n * fact(n - 1);    // 递归步骤
}
```

递归的来源有三种，课件各给了一例：

| 来源 | 含义 | 例子 |
|---|---|---|
| 定义是递归的 | 数学定义本身自指 | 阶乘、Fib、Ackerman |
| 数据结构是递归的 | 结构由自身定义 | 单链表、栈、二叉树 |
| 解法是递归的 | 解法天然分治或回溯 | Hanoi、n 皇后、迷宫 |

单链表是"结构递归"的典型：长度为 n 的单链表 = 第一个结点 + 一个长度为 n-1 的单链表。所以遍历链表可以写成

```cpp
void printTail(Node *f) {
    if (f->link == NULL) cout << f->data;  // 链尾
    else printTail(f->link);
}
```

## 二、递归为什么占用栈

每次递归调用都要保存四样东西：**参数、局部变量、返回地址、返回值**。这一组叫**活动记录**（也叫栈帧）。下探时逐个压栈，返回时按相反顺序弹出——正好是后进先出。

fact(4) 的栈变化：

| 阶段 | 栈内活动记录（自底向上） |
|---|---|
| 下探到出口 | fact(4) → fact(3) → fact(2) → fact(1) → fact(0) |
| 返回 | fact(0)=1 → 1×1=1 → 2×1=2 → 3×2=6 → 4×6=24 |

所以**递归的空间复杂度 = 最大递归深度 × 单个活动记录大小**。深度为 n 的递归就是 O(n) 空间，跟它做了什么无关。这是递归与迭代最本质的差别：迭代用几个变量，递归用一个栈。

## 三、递归的代价：Hanoi 与 Fib

**Hanoi 塔**：n 个盘子从 A 经 B 移到 C，每次只能移一个且大盘不能压小盘。解法三步：把上面 n-1 个移到 B，把最大的移到 C，再把 n-1 个从 B 移到 C。

```
T(1) = 1
T(n) = 2T(n-1) + 1
```

逐层展开 $T(n) = 2T(n-1)+1 = 4T(n-2)+3 = \ldots = 2^n - 1$。n = 64 时是 $1.8\times 10^{19}$ 次移动，按每秒一亿次算要 5800 年——指数级复杂度的直观含义。

**Fib**：`Fib(n) = Fib(n-1) + Fib(n-2)`。每次调用分裂成两次，调用总数是 2Fib(n+1)-1，而 Fib 本身按 $1.618^n$ 增长。所以递归求 Fib(40) 要做上亿次调用，其中绝大多数是**重复计算**——同一棵子树被算了很多遍。这是"递归写得漂亮但跑得慢"的经典反例。

> 旁注｜Fib 的递归树里，Fib(k) 被重复计算的次数等于 Fib(n-k+1)。记忆化（把算过的值存表）能把 $O(1.618^n)$ 降到 O(n)，这就是动态规划的基本动作，考试不考，但值得知道。

## 四、把递归改成非递归

目的只有一个：省掉栈，或者至少省掉递归调用的开销。按难度分三档，绝大多数作业题落在前两档。

**第一档：尾递归 → 循环。** 递归调用是函数的最后一条语句，且返回值不再参与运算，就叫尾递归。这种递归的栈帧没有"返回后要用"的信息，可以直接改成循环：

```cpp
void rec(int a[], int n) { if (n >= 0) { cout << a[n]; rec(a, n-1); } }
void iter(int a[], int n) { while (n >= 0) { cout << a[n]; --n; } }
```

**第二档：线性递归 → 先下探、再回填。** 递归调用之后还有事要做（比如 `return n * fact(n-1)`），没法直接变循环，但可以拆成两段：先循环把 n 降到出口，再循环把结果乘回去。

```cpp
long factIter(long n) {
    long k = n, temp = 1;
    while (k > 1) --k;          // 下探到出口（这里只是走到 1）
    while (k <= n) temp *= k++; // 从出口往上乘回去
    return temp;
}
```

**第三档：单向递归 → 迭代变量。** 有多个递归调用，但都在最后，且同一层的调用之间互不影响（Fib 属于这类）。用一个临时变量保存"上一层的结果"即可，不需要栈：

```cpp
long fibIter(long n) {
    if (n <= 1) return n;
    long a = 0, b = 1;
    for (long i = 2; i <= n; ++i) { long c = a + b; a = b; b = c; }
    return b;
}
```

**通用档：显式栈。** 上面的招数都不适用时，只能自己造栈：每个栈元素存"当前参数 + 一个 tag"，tag 记录"我正处在第几次递归调用返回的位置"。第 7 讲二叉树非递归遍历用的就是这个办法。

## 五、回溯：n 皇后

**回溯**是递归的另一种典型形态：沿着一条路走到走不通，退回上一个岔口换一条路。和分治的区别是，分治把问题拆小后各自独立求解，回溯是在解空间里试错。

**n 皇后**：n×n 棋盘上放 n 个皇后，任意两个不能同行、同列、同对角线。逐行放：第 i 行尝试每一列 j，检查 (i, j) 是否被已放的皇后攻击；能放就递归放第 i+1 行；放不下就撤销（回溯）。

用三个标记数组把"是否被攻击"变成 O(1) 判断：

| 数组 | 含义 | 下标 |
|---|---|---|
| `col[j]` | 第 j 列是否已有皇后 | 0..n-1 |
| `md[k]` | 第 k 条主对角线（左上—右下）是否已有皇后 | k = n + i - j - 1，0..2n-2 |
| `sd[k]` | 第 k 条次对角线（右上—左下）是否已有皇后 | k = i + j，0..2n-2 |

主对角线上 i-j 恒定，次对角线上 i+j 恒定，这两个下标就是"把斜线编号"。n = 8 时有 92 个解——第七节的程序会把这个数算出来。

## 六、广义表

**广义表**是线性表的推广：n（n ≥ 0）个表元素组成的有限序列 $LS = (a_0, a_1, \ldots, a_{n-1})$。每个 $a_i$ 要么是**原子**（单个数据元素），要么是**子表**（又是一个广义表）。

- **表头** $Head(LS) = a_0$，是第一个元素本身；
- **表尾** $Tail(LS) = (a_1, \ldots, a_{n-1})$，**去掉表头后剩下的表**，注意它是表不是元素。

| 例子 | 长度 | 表头 | 表尾 | 深度 |
|---|---|---|---|---|
| A = () | 0 | 无 | 无 | 1 |
| B = (6, 2) | 2 | 6 | (2) | 1 |
| C = ('a', (5, 3, 'x')) | 2 | 'a' | ((5,3,'x')) | 2 |
| D = (B, C, A) | 3 | B | (C, A) | 3 |

**长度**是顶层元素个数；**深度**是括号嵌套的层数：空表深度 1，非空表的深度 = 1 + 各子表深度的最大值。

这个定义是递归的：LS 由原子和子表组成，子表又是 LS。所以广义表的所有基本操作都写成递归：

| 操作 | 递归结构 |
|---|---|
| 求长度 | `Length(ls) = ls 为空 ? 0 : 1 + Length(ls->tlink)` |
| 求深度 | `Depth(ls) = 空 ? 1 : 1 + max{ Depth(子表) }` |
| 复制 | 复制当前结点 → 若是子表则递归复制子表 → 递归复制后继 |
| 删除值为 x 的结点 | 先在当前层循环删，遇子表递归进去删 |
| 判断相等 | 结构相同且对应原子值相等，遇子表递归比较 |

**存储表示**有两种（课件都讲了，考概念题时容易混）：

- **tag 式**：一个标志位 `tag` 区分原子/子表，`link` 指向同层下一个结点。简单，但没法表达"共享"。
- **utype 式**：`utype = 0/1/2` 分别表示表头结点、原子、子表；表头结点存**引用计数** `ref`，用来支持多个表共享同一个子表。

引用计数解决的是析构问题：一个子表被 D 和 E 同时引用时，删 D 不能把子表一起删掉。所以析构时先把 `ref` 减 1，减到 0 才真正释放。

> 旁注｜广义表的"共享"在工程上对应的是引用计数（`std::shared_ptr`）与写时复制。课件用一页讲 `F = (4, F)` 这种自引用表，正是在提醒你：递归结构 + 共享 = 需要一套所有权规则，否则析构会漏或会崩。

## 八、易错点

1. 递归出口必须覆盖所有终止分支。n 皇后里"第 i 行所有列都试过"也是一个出口，漏了就会越界。
2. 回溯时必须**撤销标记**（`col[j]=md[...]=sd[...]=0`），漏一句会导致后面所有分支都无解。
3. Hanoi 的 T(n)=2T(n-1)+1 里，那个 "+1" 是移动最大盘的那一步，不是两次递归调用的开销。
4. 表尾是表：Tail((a,b,c)) = (b,c)，不是 b。Head(Tail(L)) 才是第二个元素。
5. 广义表的深度从 1 起算，空表深度是 1 不是 0；求深度时是"各子表深度的最大值 +1"，不是求和。
6. 递归深度大时不是"慢"，是可能**栈溢出**。改非递归的第一动机常常是空间，不是时间。

## 十、一句话带走

递归把"规模"换成"栈"：每深一层就多一份活动记录，所以能不能用递归，取决于深度和空间，而不取决于代码好不好看。
