# 学案 08 · 二叉树（续）：计数、线索、堆、霍夫曼

对应课件 `课件/chapter-6-2-full.pptx`（88 页）｜教材：殷人昆《数据结构》第 3 版，第 6 章后半

上一讲把二叉树遍历写成了递归。这一讲要解决的四个问题，都源于同一个不满：**遍历依赖栈，而栈是额外开销**。线索化把空指针变成线索，堆把完全二叉树变成数组，霍夫曼把路径长度压到最小，计数则回答"n 个结点能长成多少种树"。

## 一、n 个结点能构成多少棵二叉树

设 $b_n$ 为 n 个结点互不相同的二叉树棵数（结点按前序编号为 1..n，只数形状）。根占 1 个，左子树 i 个结点有 $b_i$ 种，右子树 n-1-i 个有 $b_{n-1-i}$ 种，两边独立组合：

$$
b_0 = 1, \qquad b_n = \sum_{i=0}^{n-1} b_i \, b_{n-1-i}
$$

前几项：$b_0=1$，$b_1=1$，$b_2=2$，$b_3=5$，$b_4=14$，$b_5=42$。这就是 **Catalan 数**，通项

$$
b_n = \frac{C(2n, n)}{n+1}
$$

其中 C(2n, n) 是从 2n 个位置里取 n 个的组合数 2n!/(n!·n!)。

为什么和"出栈序列"是同一个数：二叉树的前序序列是递归遍历的**进栈**顺序，中序序列是**出栈**顺序，所以不同二叉树 ↔ 不同出栈序列，一一对应。n 个元素有 $b_n$ 种合法出栈序列，第 5 讲自测第 4 题的答案就是它。

## 二、线索化二叉树

### 2.1 动机

n 个结点的二叉链表有 2n 个指针域，真正指向子女的只有 n-1 个，剩下 **n+1 个是空的**。同时，每次遍历都要借助栈，或者要反复找前驱后继。

线索化把这两件事一次解决：**用那 n+1 个空指针，存放该结点在某种遍历次序下的前驱/后继**，这种指针叫**线索**（thread）。为了区分"指针指子女"还是"指针是线索"，每个结点加两个标记位：

| 标记 | 含义 |
|---|---|
| `ltag = 0` | leftChild 指向左子女 |
| `ltag = 1` | leftChild 指向前驱线索 |
| `rtag = 0` | rightChild 指向右子女 |
| `rtag = 1` | rightChild 指向后继线索 |

中序线索化后，中序序列的第一个结点左线索为空，最后一个结点右线索为空。其余结点的空指针全部被线索填满。

### 2.2 建线索

中序遍历一遍，随时记着"上一个访问的结点" `pre`：

- 若当前结点 `p` 的左指针为空，让 `p->leftChild = pre`，`p->ltag = 1`；
- 若 `pre` 的右指针为空，让 `pre->rightChild = p`，`pre->rtag = 1`；
- 然后 `pre = p`，继续遍历。

一遍 O(n)，不需要额外空间（除了递归栈）。

### 2.3 在线索上找前驱后继

| 目标 | 做法 |
|---|---|
| 中序第一个结点 | 从根沿左链走到 `ltag == 1` 的结点 |
| 中序最后一个结点 | 从根沿右链走到 `rtag == 1` 的结点 |
| `p` 的后继 | `rtag == 1` 则就是 `p->rightChild`；否则是**右子树的中序第一个结点** |
| `p` 的前驱 | `ltag == 1` 则就是 `p->leftChild`；否则是**左子树的中序最后一个结点** |

有了"找后继"，中序遍历就变成一条 for 循环：

```cpp
for (Node *p = First(root); p; p = Next(p)) visit(p);
```

没有栈、没有递归，空间 O(1)。这是线索化最直接的收益。

### 2.4 插入与删除

在 `s` 之后插入 `r`，分两种情况：

- `s` 的右指针是**线索**：把这条线索转给 `r`，`r` 的右指针指向它；`r` 的左指针指向 `s` 并置为线索；`s` 的右指针改指 `r`。
- `s` 有右子树：把 `r` 当成 `s` 的后继的左子女插入，或者把原右子树挂到 `r` 的右边（两种都合法，选一种实现）。

删除 `t` 的右子女 `r`，按 `r` 有无左右子树分四种情况，核心动作都是"把 `r` 的子树接回 `t`，并修补子树边界结点的线索"。课件画了四张图，考试更可能让你判断"删完之后谁的线索变了"。

> 旁注｜前序线索与后序线索也能建，但**后序线索找后继需要父指针**（后继可能是父结点），所以后序线索树通常要带 `parent` 域，代价比中序大。课件只要求知道"中序线索最常用"。

## 三、堆

**堆**是一棵**完全二叉树**，且每个结点的值都不小于（或不大于）其子女的值。前者叫最大堆，后者叫最小堆。

因为是完全二叉树，堆直接用数组存，父子关系靠下标算：

```
a[i] ≥ a[2i+1]，a[i] ≥ a[2i+2]        （最大堆）
```

### 3.1 两个调整动作

**SiftDown（向下调整）**：`a[i]` 比子女小，就和较大的那个子女交换，一路沉到底。用于"删除堆顶"和"建堆"。

**SiftUp（向上调整）**：`a[i]` 比父结点大，就和父结点交换，一路上浮到根。用于"插入"。

两者都是沿一条路径走，高度 O(log n)。

### 3.2 建堆为什么是 O(n) 而不是 O(n log n)

从**最后一个非叶结点**（下标 (n-2)/2）开始，倒着对每个结点做 SiftDown。直觉上每个结点 O(log n)，一共 O(n log n)——但这是松估计：越靠下的结点越多，它们能沉的距离越短。设 h 为结点下沉能走的最大层数，高度为 h 的那一层约有 $n/2^{h+1}$ 个结点，精确求和

$$
\sum_{h=0}^{\log n} \left( \frac{n}{2^{h+1}} \right) \cdot h = O(n)
$$

所以建堆是 **O(n)**。这个结论常考，也常被写错。

### 3.3 插入、删除、堆排序

- 插入：放到数组末尾，SiftUp，O(log n)。
- 删除堆顶：把末尾元素搬到堆顶，SiftDown，O(log n)。
- **堆排序**：先建最大堆 O(n)，然后重复"堆顶与末尾交换 → 堆大小减 1 → 对新堆顶 SiftDown"，共 n-1 轮，每轮 O(log n)，总计 **O(n log n)**，原地排序，空间 O(1)。

堆排序不稳定，但最坏也是 O(n log n)，这是它相对快排的优势。

## 四、霍夫曼树与编码

### 4.1 路径长度

- 两结点间的**路径长度** = 路径上的边数；
- 树的**路径长度 PL** = 所有结点到根的路径长度之和；
- **外部路径长度 EPL** = 所有叶结点到根的长度之和；
- **内部路径长度 IPL** = 所有非叶结点到根的长度之和。

对同一组叶结点，PL 最小的树接近完全二叉树——但加上"权值"之后，最优结构就变了。

### 4.2 带权路径长度与霍夫曼树

给 n 个叶结点各赋一个非负权值 $w_i$，叶结点到根的长度为 $l_i$，则

$$
WPL = \sum_{i=1}^{n} w_i \, l_i
$$

**WPL 最小的扩充二叉树**叫**霍夫曼树**。构造方法（贪心）：

1. 每个权值建一棵只有一个结点的树，放进森林 F；
2. 反复从 F 中取**两个根权值最小**的树，合并成一棵新树，根的权值为两者之和；
3. 新树放回 F，直到 F 只剩一棵。

权值越大的叶离根越近，这就是"最优"的直观来源。整个过程用最小堆实现，O(n log n)。

### 4.3 霍夫曼编码

把每个字符的出现频度当权值建霍夫曼树，左分支记 0、右分支记 1，从根到叶的路径就是该字符的编码。性质：

- 频度高的字符编码短，总编码长度 = WPL，达到最小；
- 没有任何一个编码是另一个的前缀（**无前缀码**），所以解码不需要分隔符，从左往右走树即可；
- 编码长度不固定，叫变长编码。

课件例子：字符 {A, T, C, S}，频度 {7, 5, 4, 2}。等长编码要 2 位/字符，总长 (7+5+4+2)×2 = 36；霍夫曼编码为 A:0、T:10、C:110、S:111，总长 7×1 + 5×2 + 4×3 + 2×3 = 35。

编码不是唯一的：合并时谁放左谁放右可以由你定，左右互换只让 0/1 互换，WPL 不变。本讲的程序把权值小的放左边，所以它给出的 C 与 S 编码会和上面这张表对调——这是正常的，不是 bug。

> 旁注｜霍夫曼编码是**静态**的：必须先统计全文频度。实际压缩工具（gzip 的 deflate）用自适应 Huffman 或算术编码，省掉两遍扫描，但原理同源。

## 六、易错点

1. 线索化时 `ltag/rtag` 的语义是"指针是不是线索"，不是"有没有子女"。`ltag = 0` 表示指向真子女。
2. 中序线索找后继时，`rtag == 0`（有右子树）不能直接返回右子女，要返回**右子树的最左下结点**。
3. 建堆从最后一个非叶结点开始，下标是 (n-2)/2，不是 n/2。
4. 建堆 O(n)，堆排序 O(n log n)，两者别混。
5. 堆排序时交换堆顶与末尾之后，待调整范围要减 1，否则会把已排好的元素又搅乱。
6. 霍夫曼编码的前缀性质来自"字符只在叶结点"，若允许字符在内部结点就会产生前缀冲突。
