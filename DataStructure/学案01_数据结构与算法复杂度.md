# 学案 01 · 数据结构与算法复杂度

> **本章地位**：数据结构的"总纲"。后面每一个结构（链表、树、图、哈希）都在回答同一个问题——**用什么存、怎么操作、付出什么代价**。而"代价"就是这里讲的**复杂度**。

---

## 一、核心概念

### 1.1 数据、数据元素、数据结构
- **数据(data)**：能被计算机处理的信息集合。
- **数据元素(data element)**：数据的基本单位，如一条记录、一个整数。
- **数据结构(data structure)**：数据元素之间的**逻辑结构** + **存储结构** + **定义在其上的运算**。

> 工程师一句话：**数据结构 = 组织数据的方式 + 操作方式。**

### 1.2 逻辑结构 vs 存储结构
| 层次 | 含义 | 例子 |
|------|------|------|
| 逻辑结构 | 数据之间抽象的关系 | 一对一(线性)、一对多(树)、多对多(图) |
| 存储结构 | 在内存里怎么放 | 顺序存储(数组)、链式存储(指针)、索引、散列 |

**关键**：同一个逻辑结构，可以用不同存储结构实现。比如线性表既可以用**数组**也能用**链表**。

### 1.3 抽象数据类型 ADT
ADT 是**从使用者的角度**描述：数据 + 允许的操作，而不关心怎么存。
```
ADT 栈 {
    数据：一串元素，一端进一端出
    操作：push(入栈)、pop(出栈)、top(取栈顶)、isEmpty(判空)
}
```
> 工程师视角：ADT 就是**接口/抽象**。`std::stack` 只告诉你"能 push/pop"，不告诉你内部是数组还是链表——这正是"封装/抽象"。

## 二、算法与复杂度

### 2.1 算法特性
1. 有穷性 2. 确定性 3. 可行性 4. 有输入 5. 有输出

### 2.2 什么是时间复杂度
时间复杂度用**基本操作的执行次数**来描述，不看具体机器快慢，只关心**随数据规模 n 增长的趋势**。

用 **Big-O 记号**表示"增长最快的项"：

| 记号 | 名称 | 例子 |
|------|------|------|
| O(1) | 常数 | 取数组下标 `a[i]` |
| O(log n) | 对数 | 二分查找 |
| O(n) | 线性 | 遍历数组 |
| O(n log n) | 线性对数 | 归并排序、快排平均 |
| O(n²) | 平方 | 冒泡、双重循环 |

**常见增长速度（越大越慢）**：`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)`

> 工程师视角：当 n 从 10⁰ 涨到 10⁶ 时，O(n²) 会从 1 涨到 10¹² —— **指数/平方增长会瞬间压垮程序**，这就是为什么"算法好"比"机器快"重要。

### 2.3 算复杂度的三步法
1. 找到**基本操作**（最内层循环里那条语句）。
2. 看它**随 n 执行多少次**（数循环层数、看循环变量变化）。
3. 取**增长最快的项**，去掉系数和低阶项。

## 三、复杂度计算示例（重点练）

### 例 1：单重循环
```c
for (int i = 0; i < n; i++) {
    sum += i;        // 执行 n 次
}
```
基本操作执行 n 次 → **O(n)**。

### 例 2：双重循环
```c
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        sum += a[i][j];   // 执行 n*n 次
    }
}
```
→ **O(n²)**。

### 例 3：循环变量不按 1 增长（对数）
```c
for (int i = 1; i < n; i = i * 2) {
    // 执行 k 次，2^k < n，所以 k = log2(n)
}
```
→ **O(log n)**。

### 例 4：两个先后循环
```c
for (int i = 0; i < n; i++) { /* n */ }
for (int i = 0; i < n; i++) { 
    for (int j = 0; j < n; j++) { /* n*n */ }
}
```
总次数 n + n² → 取最高项 → **O(n²)**。

### 例 5：递归
```c
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);   // 递归 n 次
}
```
每次调用 O(1)，共调用 n 次 → **O(n)**。

### 例 6：嵌套但内层受 i 影响
```c
for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) { /* j 执行 i 次 */ }
}
// 总次数 0+1+2+...+(n-1) = n(n-1)/2
```
→ **O(n²)**。

## 四、空间复杂度

空间复杂度衡量**算法额外占用的内存**（不含输入本身）。
- 原地操作、只用了少量变量 → **O(1)**。
- 需要一个和 n 等大的数组 → **O(n)**。
- 递归深度为 n，每层占一个栈帧 → **O(n)**。

> 工程师视角：**空间换时间** 是常见取舍。例如用哈希表 O(n) 空间，把查找从 O(n) 降到 O(1)。

## 五、上机任务

### 任务 A：统计复杂度
编写程序，对输入规模 n 从 10 到 100000，分别运行 O(n) 和 O(n²) 的求和函数，用 `clock()` 计时，打印耗时，直观感受两者差距。

```c
#include <stdio.h>
#include <time.h>

long long sumOn(int n) {          // O(n)
    long long s = 0;
    for (int i = 0; i < n; i++) s += i;
    return s;
}

long long sumOn2(int n) {         // O(n^2)
    long long s = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            s += j;
    return s;
}

int main() {
    int n = 10000;
    clock_t t1 = clock();
    sumOn(n);
    clock_t t2 = clock();
    printf("O(n)   : %.6f s\n", (double)(t2 - t1) / CLOCKS_PER_SEC);

    t1 = clock();
    sumOn2(n);
    t2 = clock();
    printf("O(n^2) : %.6f s\n", (double)(t2 - t1) / CLOCKS_PER_SEC);
    return 0;
}
```

## 七、本章小结（工程师视角）

> **数据结构 = 组织 + 操作；复杂度 = 操作代价。**
> 学完本章，你拿到了判断一切结构的"标尺"：往后每学一个结构，都要问自己——
> ① 它怎么存？② 增删查改各多少代价？③ 什么场景用它、什么场景换别的？
